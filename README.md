## Description

A Python program that reads mathematical expressions from a text file (`input.txt`), evaluates each expression using a **stack-based algorithm**, and writes the results to another text file (`output.txt`). The output keeps the same layout as the input: one result per line, with the same separator lines between results.

The program does **not** use Python's `eval()` or any external library for evaluation. All arithmetic is done through the `Stack` class.

## Objectives

- Implement a `Stack` class with `push`, `pop` and `peek` operations.
- Use stacks to evaluate expressions containing `+`, `-`, `*`, `/`, parentheses and operator precedence.
- Read expressions from `input.txt` and write results to `output.txt` in the same format.

## Input Format (`input.txt`)

- Each expression is on its own line.
- Expressions are separated by a line containing only a separator, such as `-----`.
- Spaces between numbers and operators are optional (`3+5*2` and `3 + 5 * 2` are both valid).

Example:

```text
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

**Supported:** whole numbers, decimal numbers, `+`, `-`, `*`, `/`, parentheses (including nested), and a minus sign in front of a number or bracket (e.g. `-3 + 5`, `2 * -3`).

**Separator rule:** a line is a separator if it has at least 3 characters, all identical, and the character is not a letter, digit, `.`, `(` or `)`. So `-----`, `=====` and `*****` are separators. A lone `-` or `--` is *not* a separator and is reported as a malformed expression.

**Blank lines** are ignored.

## Output Format (`output.txt`)

- Each result is on its own line, in the same position as its expression.
- Separator lines are copied exactly as they appear in the input.
- Whole-number results are shown without `.0` (13, not 13.0). Other results are shown as decimals, rounded to 10 decimal places (e.g. `7 / 2` gives `3.5`).
- If an expression cannot be evaluated, the line `Error: <reason>` is written in its place and the program continues with the remaining expressions.

Output for the example input above:

```text
13
-----
16
-----
-10
```

| Error message | Cause |
|---|---|
| `Error: Division by zero` | e.g. `5 / 0` |
| `Error: Mismatched parentheses` | e.g. `(3 + 4` or `3 + 4)` |
| `Error: Malformed expression` | e.g. `3 +`, `3 + * 2`, `3 4`, `()` |
| `Error: Invalid character 'x'` | a character that is not a digit, operator, bracket or space |
| `Error: Invalid number '1.2.3'` | a number with more than one decimal point |
| `Error: Number too large` | a result too large to represent |

If `input.txt` is missing, unreadable, or contains no expressions, the program prints a message and stops without creating `output.txt`.

## Stack Implementation

The `Stack` class is built on a Python list. The **end** of the list is the **top** of the stack, so every operation is fast.

| Operation | Description | Time |
|---|---|---|
| `push(item)` | Puts `item` on top of the stack | O(1) amortized |
| `pop()` | Removes and returns the top item (raises `StackUnderflowError` if empty) | O(1) |
| `peek()` | Returns the top item without removing it (raises `StackUnderflowError` if empty) | O(1) |
| `is_empty()` | Returns `True` if the stack has no items | O(1) |
| `size()` | Returns the number of items | O(1) |

`is_empty()` and `size()` are helper operations added because the evaluator needs them; the assignment requires `push`, `pop` and `peek`.

## Algorithm Overview

Each expression is evaluated using **two stacks**:

- a **number stack** for operands and intermediate results;
- an **operator stack** for operators and `(` markers that are waiting.

The expression is first split into tokens (numbers, operators, brackets). Then, for each token:

1. **Number:** push it on the number stack.
2. **`(`:** push it on the operator stack.
3. **`)`:** apply operators until `(` is on top, then remove the `(`.
4. **Unary minus** (a `-` at the start, after `(`, or after another operator): push it on the operator stack as a negation.
5. **`+ - * /`:** while the operator on top of the stack has **equal or higher precedence**, apply it first; then push the new operator.

After the last token, the remaining operators are applied. The one value left on the number stack is the result.

Precedence: `*` and `/` rank higher than `+` and `-`. Using "equal or higher" means operators of the same level are applied left to right (`10 - 4 - 3` gives 3).

**Key functions in `main.py`:**

| Function / class | Purpose |
|---|---|
| `Stack` | Stack data structure |
| `tokenize(expression)` | Splits text into tokens |
| `apply_one_operator(numbers, operators)` | Applies one operator to the top number(s) |
| `evaluate_expression(expression)` | The two-stack evaluation algorithm |
| `is_separator(line)` | Detects separator lines |
| `read_input_file(path)` | Reads `input.txt` into a list of entries, in order |
| `format_result(value)` | Formats numbers (13.0 becomes 13) |
| `evaluate_entries(entries)` | Evaluates all expressions, copies separators |
| `write_output_file(path, lines)` | Writes `output.txt` |
| `main()` | Runs the whole program |

**Complexity:** evaluating an expression with *n* tokens takes O(n) time and O(n) space, because each token is pushed and popped at most once.

## Assumptions

- Every non-blank line that is not a separator is treated as one expression.
- Division is true division (`7 / 2` is 3.5).
- Only the operators `+ - * /`, parentheses, whole and decimal numbers, and spaces are supported.
- Input files are plain text (UTF-8).

## Limitations

- No exponents, functions, variables, or percent signs.
- Numbers are stored as Python floats, so very large results lose precision (floats are exact only up to about 9 x 10^15).
- Results are rounded to 10 decimal places.
- Blank lines in the input are not reproduced in the output.
- Only the separator forms described above are recognized.
